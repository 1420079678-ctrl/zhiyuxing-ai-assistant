# Usage Guide

[中文](usage-guide.md) | [English](usage-guide.en.md)

This document explains how to run the project, configure environment variables, and troubleshoot common issues.

## Runtime Modes

### 1. Local Demo Mode

- available by default
- does not require `OPENAI_API_KEY`
- `/chat` returns built-in supportive replies
- combines local knowledge snippets, session memory, and rule-based risk handling
- useful for previewing the page, APIs, and the overall flow

### 2. Model Mode

- requires the API key that matches the current provider
- supports `OPENAI_API_KEY`
- also supports `DEEPSEEK_API_KEY`
- optional settings include `OPENAI_BASE_URL`, `MODEL_NAME`, `MODEL_PROVIDER`, and `MODEL_API_KEY_ENV`
- `/chat` calls an OpenAI-compatible API and returns real model output
- useful for validating real model behavior

## Environment Variables

See the root-level `.env.example` file for a reference configuration.

| Variable | Description | Required |
| --- | --- | --- |
| `OPENAI_API_KEY` | API key for OpenAI-compatible providers; if empty, the app falls back to local demo mode | No |
| `DEEPSEEK_API_KEY` | API key for DeepSeek | No |
| `OPENAI_BASE_URL` | Base URL of the OpenAI-compatible API | No |
| `MODEL_NAME` | Name of the model to call | No |
| `MODEL_PROVIDER` | Display name shown in the page, such as `OpenAI` or `DeepSeek` | No |
| `MODEL_API_KEY_ENV` | Which key variable the app should read first, such as `OPENAI_API_KEY` or `DEEPSEEK_API_KEY` | No |
| `MODEL_TEMPERATURE` | Temperature parameter for supported models | No |
| `DEMO_MODE` | Set to `true` to force local demo mode | No |
| `CHAT_DB_PATH` | Local SQLite path for chat sessions; defaults to `data/zhiyuxing.db` | No |

## Local Startup

### 1. Create a Virtual Environment and Install Dependencies

```bash
python -m venv .venv
.venv\Scripts\activate
python -m pip install -r requirements.txt -r requirements-dev.txt
```

### 2. One-Click Model Setup

Recommended scripts:

```powershell
.\setup-openai.ps1
.\setup-deepseek-chat.ps1
.\setup-deepseek-r1.ps1
```

The matching `.bat` files can also be used.

These scripts:

- initialize `.env`
- write the correct `OPENAI_BASE_URL`
- write `MODEL_NAME` and `MODEL_PROVIDER`
- set `MODEL_API_KEY_ENV`
- preserve existing unrelated settings where possible

These scripts do not remove the need for API keys. They only write the recommended provider preset:

- `.\setup-openai.ps1`: still requires `OPENAI_API_KEY`
- `.\setup-deepseek-chat.ps1`: still requires `DEEPSEEK_API_KEY`
- `.\setup-deepseek-r1.ps1`: still requires `DEEPSEEK_API_KEY`

If no valid key is provided, the project will continue to run in local demo mode.

### 3. Manual Environment Setup

```powershell
Copy-Item .env.example .env
```

### 4. Preflight Check

```powershell
.\.venv\Scripts\python scripts\check_model_config.py
```

This checks:

- which key variable the current model will read
- whether `.env` is actually ready for real model calls
- whether `OPENAI_BASE_URL` and `MODEL_NAME` look mismatched
- whether known compatibility rules such as `deepseek-reasoner` have been handled

If a real key is already configured, you can also run:

```powershell
.\.venv\Scripts\python scripts\check_model_config.py --probe
```

This sends a minimal real request to verify that the current API can actually be called by the project.

### 5. Start the Service

```bash
python -m uvicorn app:app --reload
```

If your system environment is missing project dependencies, prefer the repository virtual environment:

```powershell
.\.venv\Scripts\python -m uvicorn app:app --reload
```

You can also run:

```powershell
.\start-web.ps1
```

Or double-click `start-web.bat`.

## FAQ

### Why does the app still return responses even when no API key is configured?

Because the project supports local demo mode by default. This keeps the UI and API usable immediately after cloning.

The current demo mode is not only a single static template. It also uses:

- recent conversation history
- local knowledge snippets
- rule-based risk detection

### Do the one-click setup scripts mean no API key is needed?

No. The setup scripts only write the recommended provider configuration into `.env`.

- The OpenAI preset still needs `OPENAI_API_KEY`
- The DeepSeek presets still need `DEEPSEEK_API_KEY`

If the key is empty, the app falls back to local demo mode, so the page can still return content, but that content is not generated by an online model.

### Why does the app still run in demo mode even after I configured an API key?

First, check whether `DEMO_MODE=true` in `.env`.

Then check whether the current model is reading the correct key variable. The safest way is:

```powershell
.\.venv\Scripts\python scripts\check_model_config.py
```

### Why can DeepSeek fail even if `OPENAI_API_KEY` is filled in?

Because DeepSeek should normally read `DEEPSEEK_API_KEY`, not just any available key.

The current project now handles this explicitly:

- OpenAI reads `OPENAI_API_KEY`
- DeepSeek reads `DEEPSEEK_API_KEY`
- other OpenAI-compatible providers can be configured through `MODEL_API_KEY_ENV`

### Why does `python -m pytest` fail from the system environment?

Usually because your global Python does not have the project test dependencies. Prefer:

```powershell
.\.venv\Scripts\python -m pytest -q
```

### Why does `python -m uvicorn app:app --reload` fail?

If you see an error like `No module named uvicorn`, you are probably using the system Python instead of the project virtual environment. Use:

```powershell
.\.venv\Scripts\python -m uvicorn app:app --reload
```

or run `start-web.ps1` / `start-web.bat`.

### Is DingTalk required?

No. The current project can run as a standalone web service. DingTalk is an optional integration scenario.

### Where are local chat records stored?

By default, the app stores sessions in `data/zhiyuxing.db`. You can override this path through `CHAT_DB_PATH`.

### How do I connect models such as DeepSeek R1?

The project uses an OpenAI-compatible integration approach. Update `.env` with `OPENAI_BASE_URL`, `MODEL_NAME`, `MODEL_API_KEY_ENV`, and the matching key. See:

- [model-integration.en.md](model-integration.en.md)
