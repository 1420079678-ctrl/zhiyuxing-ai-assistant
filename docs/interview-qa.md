# 面试追问速答

这份文档用于快速应对面试里最常见的项目追问，回答方向尽量短、稳、不过度包装。

## 1. 这个项目解决的是什么问题？

核心问题不是“用户不知道怎么学”，而是很多大学生在焦虑、拖延、自我怀疑的状态下很难进入学习。项目希望把情绪支持和学习建议放进同一轮对话里，让建议更贴近真实场景。

## 2. 为什么不是做一个通用聊天机器人？

通用聊天很难体现明确场景价值。这个项目刻意聚焦大学生场景，是为了把用户问题、回复风格和功能边界做得更清楚，也更容易讲清楚产品思考。

## 3. 这个项目最能体现哪些能力？

- AI 应用原型设计能力
- FastAPI 后端接口开发能力
- Prompt 约束与安全边界表达能力
- 将方案型项目整理成可运行 GitHub 作品集的能力

## 4. 为什么补了一个独立 Web Demo？

因为如果只保留钉钉版本，演示通常会受组织环境和权限限制。独立 Web Demo 可以让外部评审直接体验核心流程，钉钉则保留为真实业务落地场景说明。

## 5. 如果别人使用这个项目，需要你的钉钉权限吗？

不需要。GitHub 里的默认展示路径是独立 Web Demo，不依赖个人钉钉账号权限。只有在把项目做成钉钉企业内部应用时，才会受到组织和授权模型影响。

## 6. 为什么要强调“已实现”和“规划中”的区别？

因为实习项目最怕把方案写成已上线能力。明确边界能提升可信度，也能让面试官更容易判断当前完成度和后续扩展方向。

## 7. 当前技术实现里最关键的部分是什么？

当前最关键的是三部分：FastAPI 接口封装、系统提示词约束、独立 Demo 页面。这三部分共同决定了项目是否既能跑起来，又能讲清楚设计思路。

## 8. 做这个项目时有哪些安全边界考虑？

项目把 AI 定位为情绪支持和学习建议辅助工具，不把模型包装成专业心理诊断工具；回复风格强调温和、具体、不做危险引导，必要时提示寻求线下专业帮助。

## 9. 工程化层面做了哪些处理？

补充了请求响应模型、环境变量配置、`pytest` 测试和 GitHub Actions CI，让项目从“只有想法”变成“最小可验证交付”。

## 10. 这个项目的下一步如果继续做，会优先补什么？

优先会补三类能力：知识库检索、风险词识别与转介流程、对话记录存储。这些能力比继续堆页面更能提升项目完整度。
