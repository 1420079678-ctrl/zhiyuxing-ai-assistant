# 简历与面试说明

这份文档用于把仓库内容转换成更适合实习投递的表达，不涉及夸大，只整理可直接复用的信息。

## 一句话项目描述

知愈星是一个面向大学生场景的 AI 心理支持与学习辅助助手作品集项目，使用 FastAPI、OpenAI SDK 和独立 Web Demo 展示“情绪支持 + 学习建议”的联动式对话能力。

## 简历描述示例

可直接参考下面这版三条式写法：

- 设计并实现面向大学生场景的 AI 心理支持与学习辅助 Demo，将情绪支持与学习建议整合进同一对话闭环。
- 基于 FastAPI、Pydantic 和 OpenAI Python SDK 完成对话接口开发，支持系统提示约束、用户输入处理和最小可运行演示。
- 搭建独立 Web Demo、pytest 测试和 GitHub Actions 持续集成，提升项目可演示性与基础工程质量。

## 面试 30 秒介绍版

这个项目的核心不是做一个通用聊天机器人，而是针对大学生常见的焦虑、拖延和学习内耗场景，设计一个“先做情绪支持，再给行动建议”的 AI 对话原型。GitHub 版本除了方案文档外，还补了可运行的 FastAPI 服务、独立 Web Demo 和基础测试，重点展示 AI 应用落地、后端实现和工程化整理能力。

## 面试 1 分钟展开版

可以从下面四点展开：

1. `问题定义`
   大学生在很多情况下不是缺少学习方法，而是缺少在压力状态下重新进入学习的能力，因此项目目标不是单纯答疑，而是把情绪支持和学习建议联动起来。

2. `技术实现`
   当前版本使用 FastAPI 提供 `/chat` 接口，结合系统提示词约束模型输出风格与边界；同时提供独立 Web Demo，便于在 GitHub 和面试场景中直接演示。

3. `工程化处理`
   仓库补充了 pytest、GitHub Actions、环境变量配置和文档分层，避免项目只停留在“方案展示”而没有最小可运行交付。

4. `边界与后续`
   当前版本仍是作品集 Demo，知识库检索、风险词转介、对话记录和真实钉钉授权接入仍可继续扩展。这种边界划分本身也是工程表达的一部分。

## 可以重点讲的技术点

- Prompt 约束：如何限制模型不输出诊断化、危险化建议。
- API 设计：如何定义请求体、响应体和错误处理。
- 演示策略：为什么用独立 Web Demo 替代“只能进钉钉组织才能演示”的方案。
- 工程质量：如何用 pytest 和 CI 保证最小交付可验证。
- 项目边界：如何区分“已实现能力”和“方案层设计”。

## 面试常见追问与可回答方向

### 1. 为什么这个项目值得做？

因为很多学习问题背后实际夹杂着情绪压力、拖延和自我怀疑。把情绪支持和学习建议割裂开，用户体验会很碎；把二者联动后，更接近真实使用场景。

### 2. 为什么不直接只做钉钉版本？

钉钉内部应用通常依赖组织环境，不适合作为唯一演示入口。作品集版本补充独立 Web Demo，可以让外部评审直接体验核心能力，同时保留钉钉作为真实落地场景。

### 3. 这个项目最能体现什么能力？

最能体现三类能力：

- AI 应用原型设计能力
- 后端接口实现与工程整理能力
- 将一个比赛/方案型项目整理成可展示 GitHub 项目的能力

### 4. 当前最大的不足是什么？

当前版本仍偏作品集 Demo，缺少更完整的知识库、持久化存储和真实风险识别流程。这一点在仓库中已经明确标注，没有把方案能力误写成已完成能力。

## 不建议的表达

为了让项目更可信，投递和面试中不建议这样写：

- 不建议写成“完整上线产品”
- 不建议写成“已经实现心理诊断”
- 不建议把钉钉方案设计直接表述成“已完成多组织可用的正式接入”

## 更稳妥的表达

- 可运行 Demo
- AI 应用原型
- 面向真实场景的最小交付版本
- 方案设计 + 最小实现
