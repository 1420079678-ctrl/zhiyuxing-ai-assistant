# 简历与面试说明

这份文档用于把仓库内容转换成更适合实习投递的表达，重点是可直接复用、不过度包装、能和 GitHub 内容对得上。

## 一句话项目描述

知愈星是一个面向大学生场景的 AI 情绪支持与学习辅助原型项目，使用 FastAPI、OpenAI SDK 和独立 Web Demo 展示“情绪支持 + 学习建议”的联动式对话能力。

## 技术关键词

- Python
- FastAPI
- Pydantic
- OpenAI API / LLM Application
- Prompt Engineering
- Web Demo Prototyping
- Pytest
- GitHub Actions

## 简历描述模板

### 模板 A：偏 AI 应用 / 后端方向

- 设计并实现面向大学生场景的 AI 情绪支持与学习辅助 Demo，将情绪支持和学习建议整合进同一对话闭环。
- 基于 FastAPI、Pydantic 和 OpenAI Python SDK 完成对话接口开发，支持系统提示约束、用户输入处理和最小可运行演示。
- 搭建独立 Web Demo、`pytest` 测试和 GitHub Actions 持续集成，提升项目可演示性与基础工程质量。

### 模板 B：偏后端工程方向

- 使用 FastAPI 设计并实现 AI 对话服务接口，完成请求响应模型封装、环境变量配置和基础错误处理。
- 针对大学生场景设计系统提示词约束，控制模型回复语气、安全边界和建议粒度。
- 补充测试与 CI 流程，并通过独立 Demo 页面降低项目演示对平台权限环境的依赖。

### 模板 C：偏产品技术结合方向

- 围绕大学生焦虑、拖延和学习内耗场景，设计“情绪支持 -> 学习建议 -> 行动拆解”的 AI 对话原型。
- 将方案型项目整理为可运行 GitHub 作品集，补充 Web Demo、接口实现、测试和文档分层。
- 单独说明钉钉接入的权限边界与展示策略，提升项目对外演示的可访问性和可信度。

## 自我介绍版本

### 15 秒版

这个项目是一个面向大学生场景的 AI 情绪支持与学习辅助 Demo，我主要做了 FastAPI 接口、Prompt 约束、独立 Web Demo 和基础工程化整理。

### 30 秒版

这个项目不是做一个泛化聊天机器人，而是针对大学生常见的焦虑、拖延和学习内耗场景，设计“先做情绪支持，再给行动建议”的 AI 对话原型。GitHub 版本除了方案文档外，还补了可运行的 FastAPI 服务、独立 Web Demo 和基础测试，重点展示 AI 应用落地、后端实现和工程化整理能力。

### 1 分钟版

这个项目的核心是把情绪支持和学习建议放进同一轮对话，而不是拆成两个割裂模块。技术上，我用 FastAPI 提供 `/chat` 等接口，用系统提示词约束模型回复的语气和边界，并补了一个独立 Web Demo，让项目不依赖钉钉组织权限也能直接演示。工程化上又加了 `pytest`、GitHub Actions 和文档分层，所以它不是只有方案，而是一个可运行、可验证、能讲清楚边界的作品集项目。

## 面试里建议重点讲的内容

- 场景定义：为什么选择“情绪支持 + 学习建议”的联动场景
- 技术实现：接口结构、Prompt 约束、最小可运行 Demo
- 演示策略：为什么要用独立 Web Demo 替代单一平台入口
- 工程化处理：测试、CI、环境变量和文档组织
- 边界意识：如何区分已实现能力和规划中能力

## 不建议的表达

- 不建议写成“完整上线产品”
- 不建议写成“已经实现心理诊断”
- 不建议把钉钉方案设计直接表述成“已完成多组织正式接入”

## 更稳妥的表达

- 可运行 Demo
- AI 应用原型
- 面向真实场景的最小交付版本
- 方案设计 + 最小实现
