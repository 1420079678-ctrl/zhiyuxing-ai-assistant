# 钉钉集成与权限说明

这份说明用于回答作品集展示中的一个关键问题：`项目如果部署在钉钉平台，外部使用方是否需要依赖个人账号或单一组织权限才能访问？`

## 结论

通常不是“必须拿到某个个人账号权限”，而是取决于应用类型和授权方式：

- 如果应用是**企业内部应用**，通常只在所属钉钉组织内可用。
- 如果目标是让**其他企业或外部评审**使用，就不能只停留在单组织内部应用形态。
- 如果调用的是**组织级接口能力**，一般还会涉及管理员授权、应用授权或用户委托授权。

## 为什么作品集不建议只交付钉钉版本

对实习评审来说，最重要的是“能不能快速看到项目能力”。如果演示必须满足下面条件，体验会明显变差：

- 先加入特定钉钉组织；
- 再由管理员开通应用；
- 再完成组织或用户授权；
- 最后才能进入页面体验。

所以更适合作品集的做法是：

1. 提供一个独立 Web Demo，让评审在浏览器里直接体验核心流程。
2. 在 README 和文档里说明：项目真实落地场景支持钉钉集成。
3. 单独补充钉钉版本的接入方式、权限模型和部署边界。

## 钉钉场景下的常见权限分层

### 1. 企业内部应用

- 这类应用更适合组织内部使用。
- 应用通常与某个组织绑定，不适合直接拿给外部企业或面试官体验。
- 如果项目当前依赖企业内部应用能力，更适合将其视为“真实部署场景”，而不是唯一演示入口。

### 2. 多组织分发或三方应用

- 如果目标是让其他组织也能安装使用，就要走面向多组织的分发思路。
- 这时重点不再是“借出个人账号”，而是“其他组织是否安装并授权该应用”。
- 从作品集角度看，这部分更适合作为架构与平台化能力说明。

### 3. 用户委托授权

- 某些能力是“应用已安装”之后，再由具体用户进行授权。
- 这更像是用户授予访问自己身份范围内的数据，而不是直接继承某个个人账号的权限。

## 展示表达建议

可以使用下面这种中性表达：

> 项目的真实设计目标包含钉钉平台接入，但为了避免演示过程依赖特定组织环境，作品集版本额外提供了独立 Web Demo。这样既能展示核心能力，也能把平台权限边界解释清楚。

这样的表述比“只能在某个内部组织里运行”更成熟，因为它体现了以下考虑：

- 可访问性；
- 权限隔离；
- 多租户分发问题；
- 作品集展示效率。

## 当前仓库采用的策略

- Web Demo 作为默认演示入口；
- 钉钉作为业务落地与平台集成场景保留在文档说明中；
- 不要求外部评审拥有特定组织权限或任何个人账号权限。
